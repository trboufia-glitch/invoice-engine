invoice.engine / api

Invoice validation API

One POST turns a messy CSV export or raw receipt text into clean JSON records, with every row that fails to reconcile flagged and its source_row reported.

Quickstart

curl -X POST YOUR_HOST/v1/normalize \
  -H "Authorization: Bearer dm_..." \
  -H "Content-Type: application/json" \
  -d '{
    "input": "Invoice Number,Currency,Subtotal,Tax,Total\nINV-1,USD,1000.00,200.00,9999.00",
    "format": "auto"
  }'
// response (abridged — issues shown are two of the three warnings plus the error)
{
  "ok": false,
  "row_count": 1,
  "summary": { "errors": 1, "warnings": 3, "avg_score": 54 },
  "records": [
    {
      "invoice_number": "INV-1",
      "issued_date": null, "due_date": null, "vendor": null,
      "currency": "USD",
      "subtotal": 1000, "tax": 200, "total": 9999,
      "score": 54,
      "issues": [
        { "field": "total", "code": "ARITHMETIC_MISMATCH",
          "severity": "error", "source_row": 2,
          "message": "subtotal 1000 + tax 200 = 1200 but total is 9999 (off by 8799)" },
        { "field": "issued_date", "code": "MISSING",
          "severity": "warning", "source_row": 2,
          "message": "issued_date not found" }
      ]
    }
  ],
  "elapsed_ms": 0.8,
  "credits_remaining": 24
}
Use the summary.errors count, not the HTTP status. A file with bad rows still returns 200 — the request succeeded, the data is what failed. Exiting on summary.errors > 0 is the whole integration.

Clean row

// input where 1000.00 + 200.00 = 1200.00
{ "ok": true, "row_count": 1,
  "summary": { "errors": 0, "warnings": 3, "avg_score": 79 } }

That still shows 3 warnings, because the columns above have no dates or vendor. Warnings are missing optional context, not defects — the row still returns ok: true. A row scores 100 once every expected field is present:

// input: Invoice Number,Invoice Date,Due Date,Vendor,Currency,Subtotal,Tax,Total
{ "ok": true, "summary": { "errors": 0, "warnings": 0, "avg_score": 100 } }

Endpoints

GET/healthLiveness and the public experiment ledger summary.
GET/v1/plansPricing, free trial size, payout ID.
GET/v1/ledgerEvery build experiment, cost and revenue, including failures.
POST/v1/keysMint a key. Returns the plaintext once; only a hash is stored.
POST/v1/normalizeThe product. Auth required, 1 credit per call.
GET/v1/usagePlan, remaining credits, lifetime calls.
POST/v1/orders?plan=proCreate a payment order for a plan.
POST/v1/orders/:id/confirmSettle with {"tx_ref":"0x…"}. Idempotent.

Request body — POST /v1/normalize

inputstring, required. Raw CSV/TSV or free text. Also accepted as csv or text.
formatauto (default), csv, or text.
toleranceArithmetic slack in currency units. Default 0.05.
max_rowsDefault 5,000, capped at 25,000. truncated flags when it bites.

Issue codes

MISSINGA required field is absent. error for id/total/currency, warning otherwise.
ARITHMETIC_MISMATCHsubtotal + tax ≠ total. error — the row is not safe to file.
TAX_RATE_MISMATCHThe stated rate doesn't produce the stated amount. warning.
TAX_NOT_REPORTEDTotal minus subtotal implies tax, but no tax field was found.
BEFORE_ISSUEDue date precedes issue date. error.
FUTURE_DATEIssue date is beyond next year. error.
PARTIAL_PAYMENTAmount due differs from total. info.
UNKNOWN_CURRENCYNot a recognised ISO-4217 code. warning.

Score

score = 100 − 25 × errors − 7 × warnings, floored at 0. A score of 100 means every check passed.

What it parses correctly

  • Numbers: 1,234.56 · 1.234,56 · 1 234,56 · 1'234.50 · accounting negatives (250.00). An empty cell is null, never 0.
  • Dates: ISO, 15/03/2026, 03/15/2026, 15-Mar-2026, Mar 15, 2026. Ambiguous slashes are disambiguated per value; 2026-02-31 is rejected.
  • Delimiters: , ; tab | — detected per file. Quoted fields with embedded delimiters survive.
  • Headers: ~50 aliases with fuzzy matching, so Doc Number (old) maps to invoice_number. Unmapped headers are reported, not guessed.

Errors

401invalid_api_key — missing, unknown, or revoked.
402insufficient_credits — response includes the top-up path and plans.
413Payload over 5 MB.
400invalid_json or missing_field.
409Order already settled, or that tx_ref was used on another order.
429Rate limited. Only unauthenticated and free-plan traffic is throttled.
Deterministic by design. No model call means no invented invoice numbers, no per-request token cost, and byte-identical output for identical input — which is what makes it safe inside a month-end close.
