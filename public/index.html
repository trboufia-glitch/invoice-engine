What it catches

Silent mismatches

A row where the totals don't reconcile — the single most common cause of a rejected invoice run.

"subtotal": 1000.00, "tax": 200.00,
"total":    9999.00
→ ARITHMETIC_MISMATCH
  1000 + 200 ≠ 9999  (off by 8799.00)

Wrong tax

A stated rate that doesn't produce the stated amount.

"subtotal":  1000.00,
"tax_rate":      20,
"tax":          100.00
→ TAX_RATE_MISMATCH
  20% of 1000 = 200 ≠ 100

Impossible dates

Calendar-invalid and internally contradictory dates.

"issued": "2026-02-31"  → rejected (Feb 31)
"issued": "2026-03-15",
"due":    "2026-02-01"  → BEFORE_ISSUE

Mixed up columns

Header names it doesn't recognise are still mapped by fuzzy match, and anything unmapped is reported instead of guessed.

"Doc Number (old)" → invoice_number
"Supplier Name"   → vendor
"Grand Total"     → total
"CCY"             → currency
Deterministic by design. No model call means no hallucinated invoice numbers, no per-request token bill, and the same input always returns the same output — which is what makes it safe to run inside an accounting pipeline.
